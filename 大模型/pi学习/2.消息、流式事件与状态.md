



## 基础消息

```ts
export type AgentMessage = Message | CustomAgentMessages[keyof CustomAgentMessages];

export type Message = SystemMessage | UserMessage | AssistantMessage | ToolResultMessage;
```

定义了一些基本的消息类型，但是也允许自定义消息类型。


## 系统消息

```ts
export interface SystemMessage {
	role: "system";
	/**首次是base prompt, 后续是追加的指令*/
	content: string | TextContent[];
	/**
	 * 命名的、有序的 prompt片段，渲染在 content之后，
	 */
	sections?: Record<string, string | null>;
	// 可用工具，有名字、描述、参数、约束采样等
	toolsAdded?: Tool[];
	// 不可用工具，只有名字
	toolsRemoved?: ToolReference[];
	timestamp: number; // Unix timestamp in milliseconds
}
```


这里 content 一开始可能只是一条基础的 prompt，后续可能会增加

 ```ts                                    
   [0] system { content: "You are a coding assistant." } // 第一条 = base prompt                            
   [1] user    { "帮我重构一下" }                                  
   [2] assistant { ... }                  
   [3] toolResult { ... }                 
   [4] system  { content: "现在开始,所有回复用中文。" } // 后面追加的指令 
   [5] user    { "继续" }                  
 ```  

这里一般 content 都是字符串类型，而 TextContent 是为后续混装 `text/img...` 等场景的。但是最终都会被拍平（`\n\n` 拼接）成字符串给到大模型。同时注意：此对象中的 content 只存文本指令。

sections 与 content 本质是一样的，都是 prompt，但是是一组“有名字的、可单独替换的 prompt 片段”。Pi 中的 sections 不是一个字符串，而是被拆分了的


```ts
const promptSections: Record<string, string> = {};  
   promptSections.preamble = "You are an expert coding assistant operating inside pi...";                          
   promptSections.tools = `${toolList}\n\nIn addition to the tools above, ...`;                                    
   promptSections.rules = buildRules(...);      
   promptSections.docs = `Pi documentation ...`;
   promptSections.cwd = cwd.replace(/\\/g, "/");
   promptSections.skills = skillsPrompt;  // 有技能时才加                  
   promptSections.project_context = renderProjectContext(contextFiles);
```


最后会被包装成带标签的文本，一般最初的 SystemMessage 为：

```ts
{                                      
     role: "system",                                                     
     content: "",                                                        
     sections: {                                                         
       preamble: "You are an expert coding assistant...",                
       tools: "<tools>\n- read: ...\n- bash: ...\n</tools>",             
       rules: "<rules>\n- Keep answers short...\n</rules>",              
       docs: "<docs>\n...\n</docs>",                                     
       cwd: "<cwd>/Users/YJ/project\n</cwd>",                            
     },                                   
     toolsAdded: [read, bash, edit, ...], 
     timestamp: 1000,                     
   }         
```

为什么要拆分？是因为中途相关内容（比如 skill）可能会变化，此时需要更新。

一次 transcript 一般长这样

 ```ts                                                                                                             
   [                           
     { role: "system",    content: "", sections: { preamble: "...", tools: "...", cwd: "..." }, toolsAdded: [read, 
 bash, edit], timestamp: 1000 },          
     { role: "user",      content: "帮我加个 login 功能", timestamp: 1001 },                                       
     { role: "assistant", content: [{ type: "text", text: "我先看看项目结构" },                                    
                                    { type: "toolCall", id: "1", name: "read", arguments: {...} }], timestamp:     
 1002 },                                                                                                           
     { role: "toolResult", toolCallId: "1", toolName: "read", content: [...], timestamp: 1003 },                   
     { role: "assistant", content: [{ type: "toolCall", id: "2", name: "edit", arguments: {...} }], timestamp:     
 1004 },                                                                                                           
     { role: "toolResult", toolCallId: "2", toolName: "edit", content: [...], timestamp: 1005 },                   
     { role: "system",    content: "", sections: { skills: "<skills>...</skills>" }, timestamp: 1006 },   // 中途  
 加载技能                                                                                                          
     { role: "assistant", content: [{ type: "text", text: "完成了" }], timestamp: 1007 },                          
   ]                                                                                                               
 ```


在运行过程中，这个 SystemMessage 就像一个快照，如果要重放或者断点续作时能直接通过这里进行恢复。


## 用户消息

```ts
export interface UserMessage {
	role: "user";
	content: string | (TextContent | ImageContent)[];
	timestamp: number; // Unix timestamp in milliseconds
}
```

用户消息就比较简单了。


## 模型消息

```ts
export interface AssistantMessage {
	role: "assistant";
	content: (TextContent | ThinkingContent | ToolCall)[];
	api: Api;
	provider: ProviderId;
	model: string;
	responseModel?: string; // Concrete model reported by the provider when different from the requested `model`
	responseId?: string; // Provider-specific response/message identifier when the upstream API exposes one
	/** Exact provider-native effort level used for this response. Absent for legacy or unmanaged responses. */
	providerThinkingLevel?: string;
	diagnostics?: AssistantMessageDiagnostic[]; // Redacted provider/runtime diagnostics for failures and recoveries.
	usage: Usage;
	stopReason: StopReason;
	deferred?: DeferredHandle;
	errorMessage?: string;
	rawStopReason?: string;
	/**
	 * Provider indication of whether the model explicitly ended its turn.
	 * Preserved for debugging and does not currently affect agent control flow.
	 */
	endTurn?: boolean;
	timestamp: number; // Unix timestamp in milliseconds
}
```




## 工具消息

```ts
export type ToolResultMessage<TDetails = JsonValue> = IsJsonCompatible<TDetails> extends true
	? {
		role: "toolResult";
		toolCallId: string;
		toolName: string;
		content: (TextContent | ImageContent)[]; // Supports text and images
		details?: JsonRepresentation<TDetails>;
		/** Usage from the tool execution itself, if available. Not part of main LLM context accounting. */
		usage?: Usage;
		isError: boolean;
		timestamp: number; // Unix timestamp in milliseconds
	}
	: never;
```
